# Windows 审查对话（本地预览）

## 先用模拟任务验收

需要 Windows 和 Node.js 22 或以上版本，无需安装 npm 依赖。

1. 双击根目录的 **本地体验审查对话.cmd**。这是本机模拟，不会启动 Codex、使用真实 API Key、扣费或修改已安装的 Hooks。
2. 在下拉框选 **任务 A**，输入“核对尺码表的单位”，点 **整理为草案**。先不要应用；点 **模拟下一次审查**，对话区应显示“没有收到任务专属规则”。
3. 在下方把草案改成你容易辨认的一句，例如“只核对厘米与英寸的换算”。点 **应用到本任务**，再点 **模拟下一次审查**：实际收到的应是你改过的文字，不是模型的原稿。
4. 切到 **任务 B**，点 **模拟下一次审查**：仍应显示“没有收到任务专属规则”。切回 A 可看到已应用版本。正常关闭窗口后，临时任务和模拟接口配置会一并清理。

“模拟下一次审查”只存在于体验版。它对临时样本调用真实的 Yo-po Stop 处理逻辑，再显示本机回环接口实际收到的规则，不会向运行中的 Codex 发出 Stop 或中断。模拟模型用固定逻辑生成示例，不代表你的模型的回答质量。

若旧预览只打开了一个黑色终端，请关闭旧终端再双击更新后的体验入口。新版终端会显示启动提示，并打开独立的「Yo-po · 审查对话」窗口。开发者可以在交互式 Windows 桌面运行 `powershell.exe -NoProfile -File test/windows-launch-smoke.ps1`，它会从实际 .cmd 入口验证窗口可见且显示两个任务，然后关闭测试窗口。

## 已配置接口的正常窗口

双击 **审查对话.cmd** 或运行 **node bin/yo-po.js review-chat**。打开、刷新和选任务都不联网。任务按本地状态更新时间排列；列表展示经过原生 Hook 去敏和截短的目标、阶段、时间与运行编号。必须主动选择一个任务，不默认选第一项。

- **发送 / 整理为草案**：使用 Yo-po 已保存的同一审查接口（没有文件时沿用已配置的环境变量）。服务商只收到这个窗口主动发送的消息和该选择下最近几轮讨论。不会自动收到任务名称、原聊天、回复摘录、日志、文件、工具输出或其他任务内容。需要背景时，请自己输入适合发给该服务商的部分。不要粘贴凭据或敏感数据。
- **应用到本任务**：仅保存编辑框中的文字，最多 2000 字符。只对这个会话的这一次运行生效；以后同一聊天的新任务不会继承。不会改全局 reviewer.md、接口或密钥，也不会向 Codex 发送消息或中断命令。
- **生效时间**：该任务下一个尚未开始的 Stop 审查才会收到专属规则，此后同一运行继续沿用。正在请求中的审查不被撤销或重发。如果这一轮恰好结束整个任务，规则不会转给别的任务。确认新版本可替换本任务原来的专属规则。
- **审查边界**：专属规则作为补充验收标准，与原始目标分开传递；不能扩大权限、免除证据、改变用户原任务。正常审查仍可按已有机制向 Codex 返回缺项，这不是把旁聊发给 Codex。
- **本地保存**：讨论与未应用草案只在当前窗口内，切换任务或关闭会清空。确认的文字存入 Yo-po 用户目录下 sessions/<会话哈希>/<运行 UUID>/review-rule.json，并会出现于使用该规则的本次常规审查输入记录。普通审查原有的数据范围没有改变。
- **任务不在列表**：只列本版原生 Hooks 报告正在派工、执行、续审或审查的任务。闭卷、禁止外部审查、主动暂停、中断、结束及旧版运行不会列出；选择失效后也不能再发送或应用。这里依据最后的本地事件，不是 Codex 进程在线探测。另一个窗口更新了同一份规则时，需要重新选择，不能静默覆盖。

## 可选：用独立配置接真实 Codex

**不需要用这一节验收模拟版。** 仅打开源码窗口不会升级现有 Hooks：0.3.1 的 Hooks 指向安装时固定的旧运行目录，不会读取新规则。不要为了预览而把现用配置覆盖掉。

要自行验证真实任务，可在**源码根目录的新 PowerShell 窗口**设置两套临时位置。以下环境变量只在这个终端及它启动的进程中生效，不用 setx：

~~~~powershell
$preview = Join-Path $env:TEMP ('yopo-codex-check-' + [guid]::NewGuid())
$env:YOPO_HOME = Join-Path $preview 'yo-po'
$env:CODEX_HOME = Join-Path $preview 'codex'
New-Item -ItemType Directory -Path $env:YOPO_HOME, $env:CODEX_HOME | Out-Null
~~~~

接真实模型会按你自己的服务商计费。若你希望复用当前 Windows 用户已保存的接口，且同意向它发送这个测试任务，可以在**同一终端**运行以下命令。只把当前用户的 provider.json 复制到这次的临时目录，不要复制现用 hooks.json、运行记录、Codex 令牌或历史记录。没有现成接口时，可改为在该临时环境按原向导配置。

~~~~powershell
Copy-Item -LiteralPath (Join-Path $HOME '.yo-po\provider.json') -Destination $env:YOPO_HOME
node bin\yo-po.js install-hooks
Start-Process -FilePath node -ArgumentList 'bin/yo-po.js','review-chat' -WorkingDirectory (Get-Location).Path -WindowStyle Hidden
codex
~~~~

在这个独立 Codex 配置中按需登录，检查并信任本次的四项 Yo-po Hooks，按 CLI 提示重开。发一个不含敏感资料、能持续一会儿的小任务，再到审查窗口点 **刷新**。不必在 Codex 中另发消息来应用草案。结束后退出这个 Codex 和审查窗口并关闭 PowerShell，日常启动方式不受影响。临时目录保留给你检查，确认不需要后可在资源管理器删除**本次生成的那个目录**。
